# Security Policy

## Reporting a Vulnerability

If you discover a security issue, do not open a public issue with exploit details.

Instead:

1. Prepare a clear report with reproduction steps, impact, and affected files or routes.
2. Share the report privately with the project maintainer.
3. Include any mitigation or temporary workaround if known.

## Response Expectations

- Valid reports should be acknowledged promptly.
- Fix timelines depend on severity, exploitability, and deployment impact.
- Sensitive details should remain private until a fix is available.

## Scope

This policy covers:

- Frontend application code
- Supabase Edge Functions
- Authentication and authorization issues
- Secrets handling and environment configuration
